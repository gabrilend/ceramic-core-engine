Task slab allocator · pipeline map

One global slab. Per-thread caches on the hot path. Single mutex on refill and drain. Cells hold task structs that travel between pool workers, so the slab itself is shared memory; per-thread caches slice it into low-contention regions.

Action walkthrough

1 · slab_create (once, at pool_create)

  1. Allocate one contiguous block: n_cells * 64 bytes. Default n_cells = 4096; configurable at pool creation.
  2. Walk the block writing the singly-linked free pointer into the first 8 bytes of every cell. Result: every cell points to its successor; the last points to NULL.
  3. Store free_head = pointer to cell 0.
  4. Allocate per-thread cache arrays sized to POOL_MAX_WORKERS * 16.
  5. Each worker thread on init pops its initial 16 cells from the global free list (one mutex acquisition each, only at startup).

2 · slab_alloc (per-task creation, hot path)

  1. Caller is a worker thread. Read its thread_idx from TLS (pool_current_worker).
  2. Local cache non-empty? → pop top, return pointer. ~3 ns.
  3. Local cache empty? → acquire global mutex; pop a batch of 16 cells off free_head; release; pop one from refilled cache; return. ~50 ns amortized.

Returned pointer is to an uninitialized 64-byte region. Caller writes the task struct fields in place.

3 · slab_free (per-task completion, hot path)

  1. Caller is the worker thread that just ran the task to completion. Read thread_idx.
  2. Push the freed cell pointer onto the local cache stack. ~3 ns.
  3. Cache size now exceeds 32? → acquire global mutex; chain the bottom 16 of the cache into the global free list; release. ~50 ns amortized.

The bottom-half drain pattern keeps recently-freed cells warm in the local cache for immediate reuse, while shedding the older half back to the global pool for other threads.

4 · slab_destroy (once, at pool_destroy)

  1. Pool quiescence has been confirmed; no thread holds a cell pointer.
  2. Free each thread's local cache array.
  3. Free the global slab block.
  4. No cell-by-cell teardown. The arena dies in one shot.

What lives in a cell

8 bytesfree-list next pointer, OR overwritten when allocated
8 bytespointer to box_runtime_state (the box this task instantiates)
4 bytestask_id (event-log correlation, per 311)
4 bytesflags (work / readiness-check / fast-fast-path; priority hint)
≤ 40 bytesinline input snapshot or pointer to a values-array if too many to fit

Total budget: 64 bytes per cell. Common case fits entirely; the values-array escape hatch handles high-arity boxes without bloating every cell.

Contention notes

  • Hot path is lock-free. 95%+ of allocations and frees touch only the calling thread's local cache. No atomics, no fences, no contention.
  • Refill / drain uses a single mutex. Frequency depends on burst size; a thread that allocates and frees 1000 tasks in a tight loop may refill / drain only ~60 times total.
  • Cross-thread free is fine. Producer thread allocates and pushes a task to the pool's queue. Consumer thread runs it and frees the cell. The free hits the consumer's local cache, not the producer's. Cells naturally migrate across caches; the periodic drain rebalances.
  • False sharing avoided by sizing cells to 64 bytes (one cache line). Two cells never share a line.
