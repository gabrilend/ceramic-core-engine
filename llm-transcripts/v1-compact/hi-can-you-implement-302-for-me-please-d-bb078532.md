**What changed across the issue's full arc**

The slot store had three separate memory pools, none recycling — an arena for variable-size values that leaked by design, malloc-per-slot for cell arrays, and malloc-per-task for the dispatch layer's scratch buffers. They are now one heap. Every byte that carries a value through a run is acquired with a reference and released when the consumer is done, with O(1) eager neighbor-merge on release and a deeper sweep at allocation-failure and at quiescence.

**Final shape of the test suite**

Slot-store suite: 17 tests (added the reclamation regression — 500 push/pop iterations that would have failed at iteration 4 against the old arena). Allocator suite: 13 tests. Dispatch suite: 7 tests, all still passing. Eleven fixture maps still run end-to-end under STRICT.

**Two follow-ons stayed outside the issue as their own future work**

The graph loader doesn't yet pipe declared producer output sizes into the allocator's pre-warm list — that's a startup-cost optimization, not a correctness gap, and belongs as part of the loader's static analysis pass. And fan-out still allocates one chunk per consumer rather than sharing one with bumped references — the optimization the design hints at, worth doing once a graph exercises it.
