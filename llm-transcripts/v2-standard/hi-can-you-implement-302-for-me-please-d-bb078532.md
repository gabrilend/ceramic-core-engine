3	Per-input-port slot store. Allocated once at graph load; each box

6	slot IDs (issue 303 keeps that boundary clean).

8	## Lifecycle
9	
10	- `slot_store_t *slot_store_create(void)` — empty store; NULL on OOM.
11	- `void slot_store_destroy(slot_store_t *s)` — frees every slot.
12	
13	## Allocation
14	
15	- `slot_id_t slot_alloc(store, cell_capacity, n_cells, flags)`
16	  - Returns `SLOT_INVALID` on bad args / OOM.
17	  - Flags: `SLOT_FLAG_NONE`, `SLOT_FLAG_TAGGED`, `SLOT_FLAG_ATOMIC_COUNTER`.
18	  - `cell_capacity` and `n_cells` are ignored for atomic-counter slots.
19	
20	## Ring-buffer ops (push / peek / pop / has_value / fill_count)
21	
22	- `int slot_push(store, id, data, size, tag)` — 0 on success, -1 on
23	  full / wrong type / size too big.

30	- `int32_t slot_fill_count(store, id)` — number of filled cells.

302 is closed.

**What changed across the issue's full arc**

The slot store had three separate memory pools, none recycling — an arena for variable-size values that leaked by design, malloc-per-slot for cell arrays, and malloc-per-task for the dispatch layer's scratch buffers. They are now one heap. Every byte that carries a value through a run is acquired with a reference and released when the consumer is done, with O(1) eager neighbor-merge on release and a deeper sweep at allocation-failure and at quiescence.

**Final shape of the test suite**

Slot-store suite: 17 tests (added the reclamation regression — 500 push/pop iterations that would have failed at iteration 4 against the old arena). Allocator suite: 13 tests. Dispatch suite: 7 tests, all still passing. Eleven fixture maps still run end-to-end under STRICT.

**Two follow-ons stayed outside the issue as their own future work**

The graph loader doesn't yet pipe declared producer output sizes into the allocator's pre-warm list — that's a startup-cost optimization, not a correctness gap, and belongs as part of the loader's static analysis pass.
