**Two things the investigation turned up that you should know about:**

The tool that writes the receiving end of every wire recognises station lines by
pattern in order to know where to insert `in` lines. If its pattern isn't
updated in the same pass, it stops finding stations in migrated maps and writes
nothing — while its `--check` mode reports clean. That's now its own step,
because a migration tool that silently succeeds at doing nothing is worse than
one that breaks.

Twenty-odd files carry old-form station lines: the four maps, the README, the
format page, nine C tests, four shell tests, and the parser's own comments. The
issue points at a grep rather than listing them, so the list can't go stale.

**One question I left open rather than deciding for you:** should the map writer
pad the kind word to a fixed ten characters so the name and box columns line up?
Padding makes dumped maps read in columns but means a map of nothing but plain
stations carries seven spaces of padding for kinds it doesn't contain. Not
padding makes every line minimal and the name column ragged. The issue currently
assumes padding.
